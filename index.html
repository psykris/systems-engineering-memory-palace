Lepakshi SE Palace — Systems Engineering Companion

V-Model Lifecycle x Lepakshi Temple Memory Palace | EN/DE Quick Reference

1 NANDI — Stakeholder Needs / Stakeholder-Anforderungen

ISO 15288 6.4.1. Identify WHO needs the system and WHY. ConOps, Lastenheft. Tools: DOORS NG, Jira, EARS. Standards: ARP 4754A, ICAO Annex 15.

Stakeholder = InteressengruppeConOps = BetriebskonzeptLastenheft = Customer Spec
ORIGIN. Everything traces back here. V-pair: Stakeholder Needs ↔ Validation.

2 GOPURAM — System Requirements / Systemanforderungen

ISO 15288 6.4.2. Lastenheft → Pflichtenheft. SMART, EARS patterns, shall-statements, acceptance criteria, bidirectional traceability. Tools: DOORS NG, Polarion, EaseRequirements.

Pflichtenheft = Supplier SpecTraceability = NachvollziehbarkeitAcceptance Criteria = Akzeptanzkriterien
Each system req SHALL trace to ≥1 stakeholder need. V-pair: System Reqs ↔ System Test.

3 NATYA MANDAPAM — Architecture / Systemarchitektur

ISO 15288 6.4.3. Decompose into subsystems. BDD, IBD, ItemFlows, SAF viewpoints. Allocate requirements. Tools: Enterprise Architect, Capella, SysML, PlantUML.

Decomposition = ZerlegungInterface Spec = SchnittstellenspezifikationSubsystem = Teilsystem
V-pair: Architecture ↔ Integration Test. Every interface must be integration-tested.

4 HANGING PILLAR — Detailed Design / Detailentwurf (V-PIVOT)

ISO 15288 6.4.4. Component-level design. HW/SW interfaces. FMEA, HARA. Bottom of the V. Tools: Enterprise Architect, MATLAB/Simulink.

Design Pattern = EntwurfsmusterFailure Mode = VersagensartSIL/ASIL = Sicherheitsintegritätslevel
V-pair: Detailed Design ↔ Unit Test. The pivot where definition meets verification.

5 MAIN SHRINE — Implementation / Implementierung

ISO 15288 6.4.5. Build it. Code, manufacture, configure. Follow coding standards. Config management. Tools: Python, Embedded C, Git, CI/CD.

Coding Standard = CodierrichtlinieConfig Mgmt = KonfigurationsmanagementChange Request = Änderungsantrag
Implementation does NOT innovate. It executes the design. Discovery → go BACK to design.

6 NAGALINGA — Verification / Verifikation

ISO 15288 6.4.6. Did we build it RIGHT? Unit test ↔ Design, Integration test ↔ Architecture, System test ↔ System Reqs. RBT. Tools: Polarion, DOORS NG.

Unit Test = ModultestIntegration Test = IntegrationstestTest Coverage = Testabdeckung
Mirrors the left side. Seven hoods = seven test levels. The serpent guards against escaping defects.

7 KALYANA MANDAPAM — Validation / Validierung

ISO 15288 6.4.7. Did we build the RIGHT thing? UAT against stakeholder needs. Abnahmetest, Entscheidungspunkte. Tools: DOORS NG, V-Modell XT.

Acceptance Test = AbnahmetestDecision Gate = EntscheidungspunktIntended Use = Zweckbestimmung
V-pair: Validation ↔ Stakeholder Needs (Nandi). The marriage of system and user.

8 SITA FOOTPRINT — Operations & Lifecycle / Betrieb & Lebenszyklus

ISO 15288 6.4.8-10. Deploy, operate, maintain, dispose. Change management, config control, feedback. The V is a circle.

Operations = BetriebMaintenance = InstandhaltungDisposal = Außerbetriebnahme
Operational experience feeds BACK to Nandi. New needs → new V cycle. "Das V-Modell sagt uns WAS. Agile sagt uns WIE."
